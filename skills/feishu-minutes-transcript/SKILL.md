# 飞书妙记文字记录提取

## 使用边界

- 仅在用户主动要求使用本 skill 时运行；不主动选择或推荐执行。
- 目标是保存原始文字记录，默认保留发言人、时间戳、原始措辞及转写错误。除非用户要求，不改写、不纠错、不总结，不下载音视频。
- 使用用户提供的链接及当前已获授权的登录会话。无法访问内容时，说明登录或访问权限阻塞，不猜测接口或读取隐藏应用状态。

## 默认直接提取页面元素

调用本 skill 就表示使用“读取页面元素并保存文本”的方法。用户说“下载文字记录”描述的是交付结果，不表示要求点击网站下载按钮；无需用户再次说明“直接复制元素”。

1. 使用浏览器工具打开链接。使用浏览器前阅读其当前工具文档，遵守会话命名、页面状态检查及标签页保留规则。
2. 打开链接，核对标题、会议时间及总时长，进入“文字记录”页签，避免误把“智能纪要”作为正文。
3. 直接执行下述页面元素提取和虚拟滚动流程，再将结果写入本地文件。不要先探索“更多”菜单，不检查或点击“导出文字记录”“下载”等入口，也不以导出权限作为页面提取的前置条件。
4. 可以点击进入“文字记录”页签、关闭遮挡弹窗等读取正文所必需的控件。禁止的是默认尝试网站导出流程，不是所有页面交互。
5. 如果偶然看到导出按钮禁用，仍按本流程读取用户有权阅读的页面内容；不要因此停止或要求所有者开启导出权限。无法阅读正文时，报告实际的登录、访问或页面加载阻塞。

只有用户明确要求“使用飞书原生导出”“点击导出按钮”等方式时，才切换为原生导出。此时在点击前注册下载等待，核验实际保存文件。不得因 DOM 提取遇到困难而自动切换到点击导出；应先检查页面结构和滚动容器，仍无法完成时说明具体阻塞。

## 从页面元素复制

### 确认结构

先读取当前页面的可访问性树或 DOM 快照，再检查一段已显示文字及其父元素。只用当前页面实际观察到的选择器、属性和工具 API。

以下是曾在飞书妙记页面观察到的结构，属于定位提示，不能直接假定仍然有效：

| 内容 | 曾观察到的元素或属性 |
| --- | --- |
| 发言段落 | `.transcript-paragraph-item` |
| 段落唯一标识 | `[data-zone-id]` 的 `data-zone-id` |
| 发言人 | `.p-user-name` 的 `user-name-content` |
| 时间戳 | `.p-time` 的 `time-content` |
| 正文 | `.paragraph-content-editor` 的 `textContent` |
| 虚拟列表内部容器 | `.rc-virtual-list-holder-inner` |

姓名和时间可能通过属性呈现，直接读取整页 `innerText` 会漏掉它们。正文由多个词语 span 组成，拼接原始 `textContent`，不要在每个 span 之间添加空格。可去除编辑器尾部的零宽占位字符，但不要删除正常空格或改动标点。

结构核实后，可参考以下只读提取表达式。通过当前浏览器工具支持的 DOM 读取 API 执行，不把它作为网页脚本注入：

```javascript
elements.map(element => ({
  id: element.querySelector('[data-zone-id]')?.getAttribute('data-zone-id'),
  speaker: element.querySelector('.p-user-name')?.getAttribute('user-name-content'),
  time: element.querySelector('.p-time')?.getAttribute('time-content'),
  text: element.querySelector('.paragraph-content-editor')?.textContent
}))
```

### 处理虚拟滚动

妙记可能只挂载视口附近的段落；一次读取 DOM 不能视为全文。

1. 从记录顶部开始，读取当前已挂载段落，保存稳定 ID、发言人、时间戳、正文及页面顺序。
2. 在文字记录面板内向下滚动约半个视口，获取新页面状态，再读取段落。不要滚动视频或整页的其他面板。
3. 按稳定 ID 去重。保留各批次的相邻关系；相同时间戳可以有不同发言，不得按时间或正文去重。不要假定不透明 ID 的字典序就是发言顺序。
4. 检查相邻批次是否有重叠段落。没有重叠时回滚补读，并减小步长。长发言可能超过一屏，不能仅根据时间戳跳跃认定遗漏。
5. 每次滚动后检查状态；可小批量连续处理，但遇到结构变化、页面异常或无法提取时停止该批次并检查原因。避免无限滚动或等待。
6. 到达列表底部后，确认最后一段内容及时间戳，继续一次小幅滚动确认没有新段落。最后发言时间可能早于录音结束，不强求两者相等。

如果中途才开始采集或发现空缺，回到相应位置补齐。若仍无法证明连续覆盖，交付时明确标记为部分记录，不声称完整。

## 保存与核验

- 默认保存 UTF-8 `.txt`，文件名为“会议标题-文字记录.txt”。使用用户指定目录；未指定时遵循当前工作区的输出目录约定。避免覆盖同名已有文件。
- 文件头记录标题、会议时间、时长、来源链接，以及“页面原始转写，未校正”的说明；正文按页面顺序排列：

```text
发言人 00:06
该段原始文字。

发言人 00:10
下一段原始文字。
```

- 通过当前工具支持的本地文件写入方式保存提取结果，尽量直接序列化已采集数据，避免人工复述或大模型重写正文。不要用浏览器未提供的内部 API、网络请求或系统剪贴板旁路搬运数据。
- 核对首尾段落、段落数、顺序及重叠连续性。对内存中的规范化正文和落盘后正文做字符数及校验值比对；文件头不参与正文比对。校验一致只能证明保存无损，不能替代虚拟列表的完整性检查。
- 最终回复给出实际本地文件链接，简短说明保留了发言人和时间戳。存在缺失、无法辨认的字段或提取范围限制时明确说明。
- 不在 skill 或通用示例中保存真实会议正文、个人信息、登录凭据或此次任务的具体链接。
